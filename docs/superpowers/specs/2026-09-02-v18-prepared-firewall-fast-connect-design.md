# v18 预备态防火墙与快速连接设计

## 背景与现场证据

v17 已解决 TUN 驱动元数据误判，但 2026-09-02 generation 2 的真实连接仍失败。日志证明 TUN 在 `10:45:02` 已创建并通过固定别名、GUID 与地址校验；最终显示“TUN 接口未就绪”并非真实原因。

本次连接的主要耗时为：

- 二进制验证：2.828 秒；
- PowerShell 网络捕获：6.852 秒；
-首次防火墙发布及活动存储验证：26.651 秒；
- 核心启动及首次 TUN 识别：6.359 秒；
- TUN 识别后等待防火墙锁：80.570 秒，随后被 120 秒连接总超时取消。

后台保护监视器从连接阶段就以 250 毫秒间隔启动。每次循环都会执行一次约 3 秒的网卡扫描、约 12–16 秒的规则发布和约 11 秒的活动存储验证。循环持续占用 `protectionRunMu`，前台 TUN 阶段无法完成后续操作。失败后现场还出现 23 条启用的产品规则，而快照、TUN、路由和核心均已消失；服务恢复使用 PowerShell 管道边枚举边删除多条规则，也出现部分删除后转入 Emergency 的行为。

这不是增加连接超时可以解决的问题。连接期、运行期监控和恢复期共用同一套全量 PowerShell 重建操作，是本轮需要替换的架构。

## 已批准决策

- 稳定网络环境下，从点击连接到 `connected` 不超过 15 秒，目标为 6–11 秒。
- 采用预备态规则池方案，不采用路由-only 降级方案。
- 断开状态允许保留本产品拥有且定义合法的 Disabled 防火墙规则；它们不阻断流量，也不计为活动残留。
- 防泄漏规则由当前每接口三条缩减为每接口一条 `Protocol Any` 公网阻断规则，并保留两条非批准 DNS 阻断规则和一条 Emergency 规则。
- 网络状态读取改用 Go 调用 Windows IP Helper API；PowerShell 只用于 Windows Firewall 写入和后台深度审计。
- 运行期监视器只在连接成功后启动，不再高频全量重建。
- UI 日志继续默认展开，但必须使用有业务含义的中文动作与精确错误分类。
- 连接任一阶段失败时，服务必须在返回失败前自动逆序恢复，不再依赖用户点击“恢复网络”。

## 目标

- 消除连接过程中后台监视器与前台状态转换的锁竞争。
- 把稳定网络下连接耗时控制在 15 秒以内。
- 保持 fail-closed：防火墙未启用并验证前不得启动核心或切换路由。
- 断开时普通网络立即恢复，Disabled 预置规则不产生流量影响。
- TUN、防火墙、网络变化、路由和恢复错误各自返回真实错误码。
- 服务崩溃、核心崩溃、网络变化或连接取消后能够自动回到可证明的安全状态。
- 将日志从底层执行器描述提升为用户能理解的连接时间线，同时保留脱敏技术详情。

## 非目标

- 不改动 VM101、电信客户端、`172.20.9.15:8080` 或 HTTP CONNECT 服务端。
- 不实现 macOS、Linux 或移动端客户端。
- 不在本轮改用 WFP callout 驱动或第三方防火墙驱动。
- 不取消防泄漏保护来换取速度。
- 不把冷连接强行伪装成 15 秒内完成；网络拓扑变化后的预备态重建可以超过 15 秒，但必须显示明确原因并以 30 秒为目标上限。
- 不在本轮隐藏调试日志或完成正式员工版视觉设计。

## 状态模型

服务维护以下互斥状态：

1. `preparing`：正在读取网络基线或创建 Disabled 预置规则；
2. `prepared`：网络基线、规则定义和所有权记录一致，所有正常规则与 Emergency 规则均 Disabled；
3. `connecting`：已锁定一个 prepared generation，正在执行连接事务；
4. `connected`：规则已启用、核心及 TUN 受控、DNS 与路由已切换；
5. `restoring`：正在逆序停止核心、恢复网络并禁用规则；
6. `failed_safe`：普通恢复无法证明完成，Emergency 已启用并拒绝新连接。

后台预备任务只允许在 `preparing` 或 `prepared` 状态运行。`connecting`、`connected` 和 `restoring` 期间不得修改预置规则定义或网络基线。

## 预备态规则池

### 规则集合

对每个受保护适配器创建一条规则：

`RegenBioOverseasAccess.BlockPublicAny.<GUID>`

规则固定为 Outbound、Block、Protocol Any、接口别名精确匹配，并使用当前策略推导出的公网远端前缀集合。另有：

- `RegenBioOverseasAccess.BlockUnapprovedDNSUDP`；
- `RegenBioOverseasAccess.BlockUnapprovedDNSTCP`；
- `RegenBioOverseasAccess.BlockPublicEmergency`。

当前七个受保护接口对应七条 Any 规则、两条 DNS 规则和一条 Emergency 规则，合计约十条。Emergency 不属于正常批量启用集合。

### 所有权与定义

规则使用产品固定组 `RegenBioOverseasAccess.Managed`，并在受保护的 ProgramData 所有权账本中记录名称、接口 GUID、接口别名、协议、端口、远端前缀集合哈希、定义版本和期望 Enabled 状态。

只有名称、分组、完整定义和账本记录全部匹配的 Disabled 规则才可作为预备资源复用。未知规则、重复名称、定义漂移或账本不匹配必须拒绝采用；服务先启用 Emergency，再进入 `failed_safe`，不能覆盖或收编不明规则。

### 生命周期

- 服务启动或断开恢复完成后构建/更新预备态，正常规则和 Emergency 均保持 Disabled。
- 连接时批量启用正常规则，Emergency 保持 Disabled。
- 连接失败或断开时批量禁用正常规则，不删除规则。
- 网卡拓扑变化时，只在代表“已断开且可连接”的 `prepared` 状态重建受影响的 Disabled 规则。
- 卸载时在证明所有规则 Disabled、无活动连接且所有权完整后删除规则与账本。

## 原生网络基线

Go 服务通过 Windows IP Helper API 读取：

- 适配器 GUID、接口索引、别名、状态与 DNS 服务器；
- IPv4 接口指标与自动指标状态；
- 默认路由、节点最佳路由、下一跳与路由指标；
- 当前网络指纹和递增的 prepared generation。

预备态保存完整可恢复基线。点击连接时重新读取轻量指纹；只有指纹与 prepared generation 匹配才可复用基线。如果不匹配，连接请求进入 `preparing`，刷新完整基线和规则池后再继续。刷新期间 UI 显示“正在更新网络保护配置”，不得显示普通连接卡顿或 TUN 错误。

网络基线必须原子写入现有受保护状态目录，并绑定策略哈希、规则定义版本和 prepared generation。缓存的二进制验证结果绑定文件标识、长度、修改时间、SHA-256、Authenticode 指纹和策略允许值；任一字段变化即重新完整验证。

## 连接事务

连接事务按以下顺序执行，并为每一步写入持久化阶段：

1. 锁定 prepared generation；
2. 快速重新读取网络指纹并确认未变化；
3. 原子保存连接前网络快照，阶段为 `captured`；
4. 批量启用正常防泄漏规则；
5. 回读名称、数量、Enabled、Action、定义版本和 prepared generation，阶段为 `protected`；
6. 生成受控 sing-box 配置并启动受 Job Object 管理的核心进程树，阶段为 `core_started`；
7. 确认启动前不存在、启动后新出现的固定 TUN GUID、别名和唯一地址，阶段为 `tun_owned`；
8. 切换 DNS、接口指标和安全路由，阶段为 `routes_active`；
9. 发布 `connected`，随后启动运行期监控。

规则启用或回读不完整时，先启用已预置的 Emergency，再自动逆序恢复。核心不得在 `protected` 之前启动。后台监视器不得在 `connected` 之前执行扫描、发布或验证。

## 断开与自动恢复

断开和所有连接失败共用一个幂等的逆序恢复器：

1. 停止运行期监控并等待 goroutine 完全退出；
2. 停止核心及整个 Job Object 进程树并证明终止；
3. 按快照恢复 DNS、接口指标和产品拥有的路由；
4. 禁用正常防泄漏规则与 Emergency；
5. 删除活动连接快照，保留 prepared 基线和 Disabled 规则池；
6. 验证启用中的产品规则、产品路由、产品 TUN、产品核心进程和活动快照均为零。

`Connect` 必须等自动恢复得到终结结果后才向 UI 返回失败。只有恢复本身无法完成时返回 `automatic_restore_failed` 并保持 Emergency。用户无需先点击“仅恢复网络”才能重试。

服务启动恢复根据持久化阶段决定逆序动作。无活动快照时只需禁用所有合法产品规则，不删除预备池。处理多条规则时必须先把查询结果完整物化，再按精确名称逐条禁用或删除，禁止把 `Get-NetFirewallRule` 的惰性管道直接接到删除命令。

## 运行期监控

运行期监控仅在 `connected` 后启动：

- 每 30 秒使用原生 API 读取一次轻量网络指纹；
- 指纹未变化时不启动 PowerShell，不写防火墙；
- 指纹变化时立即启用 Emergency，标记 `network_changed`，停止核心并自动恢复；恢复后在 disconnected 状态重建预备态；
- 每 5 分钟执行一次完整防火墙定义审计；
- 完整审计发现规则缺失、禁用、定义漂移或未知规则时，进入相同的 Emergency 和恢复流程。

不得保留 250 毫秒全量 PowerShell 重建循环。监控取消必须可等待；旧 generation 的监控不得在新 generation 或恢复完成后继续写规则。

## 错误模型

新增或明确以下错误码：

- `prepared_state_unavailable`：预备态未完成或不可用；
- `network_changed`：点击后或运行中网络指纹变化；
- `firewall_enable_failed`：正常规则无法完整启用；
- `firewall_verify_failed`：启用后的规则状态或定义不符；
- `core_start_failed`：核心进程无法启动；
- `core_not_ready`：核心进程已启动但代理能力未就绪；
- `tun_not_found`：截止时间内确实没有发现固定 TUN；
- `tun_identity_mismatch`：发现候选 TUN，但 GUID、别名或地址不符；
- `route_activation_failed`：DNS、接口指标或安全路由切换失败；
- `automatic_restore_failed`：自动逆序恢复无法证明完成。

防火墙锁等待、PowerShell 超时、监视器失败和总连接超时不得映射为 TUN 错误。每个底层错误必须在产生边界立即绑定真实 stage，Controller 只负责保留而不是重新猜测分类。

## UI 与日志

UI 顶部显示当前业务阶段、累计耗时和步骤编号，例如“正在启用防泄漏保护 · 2.1 秒 · 第 2/6 步”。

PowerShell runner 的通用文案替换为固定业务消息：

- “正在读取当前网络配置 / 当前网络配置已确认”；
- “正在枚举需要保护的网卡 / 已识别 N 个需保护接口”；
- “正在创建预置防泄漏规则 / 预置规则已准备并保持禁用”；
- “正在启用防泄漏保护 / 防泄漏保护已启用，共 N 条规则”；
- “正在核对 Windows 防火墙活动状态 / 活动规则核对通过”；
- “正在等待 sing-box TUN 网卡 / TUN 网卡已就绪”；
- “正在切换 DNS 与安全路由 / 安全路由已启用”；
- “正在恢复普通网络 / 普通网络已恢复”；
- “正在检查连接残留 / 活动残留已清零”。

第一行面向用户，缩进详情保留操作代码、generation、prepared generation、规则数量、接口数量、GUID、耗时与脱敏错误。连接失败后同一 generation 继续显示自动恢复全过程，并在终结事件中包含活动残留计数和 Disabled 预置规则计数。

“复制诊断信息”必须包含每阶段时间、失败边界、连接前后网络版本、规则启用/禁用数量、自动恢复结果和最终残留；不得包含凭据、代理认证、完整配置或完整前缀集合。

## 性能预算

稳定 prepared 状态下：

| 阶段 | 预算 |
|---|---:|
| 缓存策略与二进制校验 | 0.5 秒以内 |
| 原生网络指纹与快照确认 | 0.5 秒以内 |
| 批量启用并确认规则 | 1–3 秒 |
| 核心启动与 TUN 识别 | 3–5 秒 |
| DNS 与路由切换 | 1–2 秒 |
| 总计 | 6–11 秒，硬验收上限 15 秒 |

网络拓扑变化后的冷连接目标不超过 30 秒。冷连接不计入稳定态 15 秒门禁，但 UI 必须明确显示 prepared generation 重建及耗时。

## 测试设计

所有生产行为先写失败测试：

1. 原生网络读取与既有 PowerShell 快照的等价性测试；
2. prepared generation、策略哈希、二进制缓存和网络指纹失效测试；
3. 每接口一条 Any 规则、DNS 规则和独立 Emergency 规则的定义测试；
4. Disabled 合法规则可复用、未知或篡改规则拒绝采用的所有权测试；
5. 连接期没有后台扫描、发布或验证操作的并发测试；
6. TUN 成功后不再执行第二轮完整防火墙发布的顺序测试；
7. 监控指纹不变时零 PowerShell 写入、变化时 Emergency 优先的测试；
8. 五分钟深度审计发现篡改并自动恢复的测试；
9. 每个连接阶段注入失败后自动逆序恢复及零活动残留测试；
10. 防火墙、超时和监视器错误不会映射为 `tun_not_found` 的错误分类测试；
11. 连接失败日志继续包含完整自动恢复时间线的 ViewModel 测试；
12. 业务日志文案不再出现“固定网络操作”的文本契约测试；
13. LocalSystem 实机测试：恢复旧版 23 条规则、物化后精确禁用/删除、服务可再次启动；
14. Windows Job Object、全量 Go、race、PowerShell 5.1、脚本 AST、签名、MSI 安装/升级/卸载测试。

测试夹具不得用跳过防火墙、缩短真实规则集合或伪造 TUN 成功来通过性能门禁。性能测试记录阶段分解，避免只看总时间掩盖新的锁竞争。

## 本机验收

部署签名版本后，由用户完全退出 FlClash 并手动触发真实连接：

1. 连续执行三次连接与断开；
2. 稳定网络下三次点击到 `connected` 均不超过 15 秒；
3. Google 等批准站点可访问，内网站点和 `172.20.9.15` 始终可达；
4. 断开后普通网络立即恢复，正常规则和 Emergency 全部 Disabled；
5. 杀死核心进程后自动进入失败、恢复网络且不发生公网直连泄漏；
6. 模拟网卡变化时显示“正在更新网络保护配置”或 `network_changed`，不得显示 TUN 未就绪；
7. 冷连接目标不超过 30 秒，并显示预备态重建进度；
8. 最终活动残留为零；Disabled 预置规则数量与当前网卡拓扑一致。

代码构建、签名、安装和恢复验证由开发侧完成；真实站点访问和用户点击由用户完成，以保持测试结论独立。
