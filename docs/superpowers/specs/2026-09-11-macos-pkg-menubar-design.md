# macOS 标准安装与状态栏面板设计

日期：2026-09-11。用户已认可“标准 PKG 安装＋纯状态栏弹出面板”。本文将该方向落实为实施边界；不包含网络核心重构。

## 目标与非目标

交付一个自包含 PKG；用户无需运行终端、填写本地用户名、输入 TRUST 或另拷贝依赖。保留 macOS 自身所需的管理员和信任授权，不承诺未经签名、公证的包完全没有安全提示。

仅改 macOS 安装器和界面宿主。Windows不动、Linux暂缓。不加入企业登录、设备注册、检查更新、复制诊断摘要。保持内网限定、现有节点策略、八站点探测和默认关闭的诊断。Developer ID、System Extension、关闭 SIP/Gatekeeper、放宽 authorizationdb 均不在范围内。

## 已选方案

选择标准 PKG：通过系统 Installer 完成安装与授权，应用落在 /Applications。未选择“拖动 App 后再首次安装后台”，因为它不能省去系统权限，而且增加首次运行的失败分支。

选择状态栏弹出面板：复用 Flutter 紧凑界面，用原生 NSStatusItem 与 NSPopover 承载，不保留可见独立主窗口。未选择“仅隐藏 Dock 但保留浮动窗口”。

## 安装流程与权限

1. 打开单个 PKG；安装说明清楚区分应用与公司出口流量 CA，保留 HTTPS 检查用途及准确指纹说明，以正常图形化同意替代 TRUST 文本输入。
2. 在修改前检测现有安装、路径安全、清单与核心摘要、服务状态和目标日常账户。首次本机安装采用当前图形会话的真实本地用户，拒绝 root、loginwindow、系统账户和无法唯一映射的身份。不能把执行安装的管理员或 SSH 用户直接当作日常用户。
3. 升级保留已验证收据中的 owner UID，不静默更换控制权限。现有连接必须先断开并确认恢复；图形化提示后重试，不自动中断用户连接。无可用图形用户的无人值守部署本轮不支持，不猜测授权对象。
4. 用系统授权执行 root 安装工作。证书已有且信任有效则不重写；首次流量信任需要系统确认时，提供本机图形化引导，程序不自行收集密码、不抑制系统授权。只有后台可用、普通用户可访问且必要信任验证通过，才报告配置完成。
5. 若标准 Installer 的执行上下文仍不允许建立信任，不能把 postinstall 失败包装成成功；必须验证受支持的本机授权流程。若无法做到，则明确阻塞，不以放宽系统权限替代。用户可能仍需一次额外系统确认。
6. App 安装到 /Applications/RegenBio Access.app；服务、固定核心、配置与状态继续位于 /Library/Application Support/RegenBioAccess。程序入口和所有更新/回滚/卸载路径同步更新。

## 安装事务与旧版迁移

包先把已验证资源放进独立、root 控制的暂存目录，再由现有受约束安装逻辑激活；不得让 PKG 在 preflight 前覆盖正在使用的二进制或 journal。延续 root:wheel、私有状态目录、固定路径、清单校验和独占锁。

旧 PoC 内部 App 迁移到 /Applications：确认现有 App 归属和摘要，保留可恢复备份。/Applications 若有无法认领的同名 App，拒绝覆盖。迁移同时覆盖 App、后台、plist、收据；任一步失败回滚至上一完整状态，不留下双入口或错误成功标记。macOS 包收据不替代应用自己的事务收据，失败/重试必须测试二者的一致性。

launchd 停止需有限时地等待真正注销；查询超时或未知错误仍拒绝，不把短暂退出中或锁空闲当作安全停止。恢复不确定时保留现场，不覆盖状态。

保留明确的卸载入口和 IT 卸载方法，先断开并恢复网络，再移除本安装拥有的服务、App和新增证书；保留原有证书信任和可恢复备份。不能宣称把 App 拖入废纸篓就完成后台卸载。

## 状态栏交互

- 使用 LSUIElement；不出现 Dock 图标、Cmd-Tab 项或独立可见主窗口。应用进程与后台服务仍存在，“无独立 UI”指没有独立窗口，不是没有后台进程。
- 启动仅显示状态栏图标，不自动弹面板、不自动连接。本轮不新增登录自启动；打开应用即可出现图标。再次从 /Applications 打开已运行的应用时，展示同一个面板，不重复启动。
- 左键点击图标切换弹出/收起；面板锚定状态栏图标，点击外部或 Esc 收起。收起不触发断开或取消正在进行的操作。
- 沿用紧凑 B 布局，基准内容尺寸480×224逻辑点，主页面和详情页面相同大小。去掉窗口标题栏及最小化/关闭/放大按钮；屏幕边缘、缩放或较大文字时限制在可用区域，详情允许内部滚动，不裁掉操作入口。
- 主页面显示状态、连接/断开按钮、本次连接时长及唯一详情入口。不显示“部分站点慢”等汇总提示；真正连接失败、服务不可用和恢复失败仍如实显示。
- 详情在同一面板内切换，显示 Google、Pinterest、Gemini、ChatGPT、Claude、TikTok、Amazon、Facebook 的延迟、状态和刷新时间，保留手动测速。沿用既有后台探测周期；收起不会反复销毁引擎或额外触发测速。
- 右键菜单只保留当前状态、连接/断开、断开并退出。删除“显示主窗口”等重复或无效入口。
- 断开并退出必须等待网络恢复确认。失败时保留进程和图标，弹面板显示简短错误，不隐藏失败；连接中保持单一操作约束。退出成功后图标消失。
- 图标及面板来自同一后台状态，不用网页延迟推断隧道连接状态；网络失败不回退为伪成功。

## 组件边界

Flutter继续负责页面、状态模型和 API v1 客户端；原生宿主管理状态栏、popover、焦点、重复启动和生命周期。保留固定 Unix socket、POSIX realpath、root peer 认证及普通用户权限，不新增任意命令或路径传递接口。

安装器独立负责权限、校验、迁移与恢复，不让状态栏按钮携带管理员凭据。现有网络服务和路由身份修复保持不变。

## 验收

先测试再实现，补充宿主交互和安装生命周期回归；保持原有测试，不通过更新 golden 基线掩盖无关差异。

- 首装、升级、连接中拒绝升级、错误用户、陌生同名 App、授权拒绝、CA部分导入失败、launchd退出过渡、安装中断和回滚。
- 未管控设备的系统安全提示和本机信任授权需实际验证，不用已配置测试机替代首次安装证据；已管控设备原有CA信任不得重写。
- 安装后可在 /Applications 找到，普通用户不使用终端即可启动；面板无 Dock/独立窗口，左右键、Esc、点外、详情返回、重复启动均正常。
- 连接/断开不需重复提权；折叠/展开不会断线或重启核心；退出失败有可见反馈。
- Google/YouTube实际浏览及八站点探测、断开恢复和重连；至少60分钟与睡眠唤醒分别记录，未验证项明确列出。
