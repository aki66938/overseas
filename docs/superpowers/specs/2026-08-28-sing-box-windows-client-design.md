# Windows 一键海外访问客户端与 sing-box 网关设计

日期：2026-08-28  
状态：已完成口头评审，待书面规格确认  
范围：Windows PoC；单节点；固定测试凭据

## 1. 背景与目标

企业已通过合法合规的电信海外专线访问获准站点。电信客户端当前仅支持 Windows，并要求管理员使用政府发放的 PIN 登录。测试 VM `172.20.9.15` 已运行该客户端，能够访问 Google 等获准站点。

现场验证表明，电信能力不是虚拟网卡或系统路由，而是由以下本地进程提供的 HTTP CONNECT 上游代理：

- 地址：`127.0.0.1:8080`
- 进程：`plugin_monitor.exe`
- 所属软件：China Telecom Tianyi Security Assistant

本项目的目标是让获授权的 Windows 用户安装一个企业客户端后，只需点击一次即可让互联网 TCP 流量通过该 VM 和电信线路访问获准站点。用户无需安装电信客户端、输入 PIN、选择节点或理解代理配置。

首期不包含 AD 授权中心、macOS、普通 UDP 全量支持、多节点生产调度及 30 人并发上线。旧 WireGuard/WinNAT PoC 保留为历史验证，不作为本方案的数据通路。

## 2. 总体架构

```text
Windows 用户
  -> 一键客户端（Go UI + Go Windows 服务）
  -> 本地 sing-box + TUN
  -> Shadowsocks 2022 加密连接
  -> 172.20.9.15 上的 sing-box 服务
  -> HTTP CONNECT 上游 127.0.0.1:8080
  -> 电信海外专线
  -> 政府/运营商白名单允许的站点
```

客户端接管互联网 TCP 流量，企业内网、AD、企业 DNS、Endpoint Central（EC）以及代理节点自身地址保持直连。服务端上游不可用时必须失败关闭，不得回退到 VM 的普通默认网关。

本方案使用 sing-box 实现标准代理协议、TUN 和转发能力；自研 Go 程序负责用户体验、权限边界、配置生命周期和故障恢复，不自行实现代理协议栈。

## 3. 组件及职责

### 3.1 Windows 用户界面

Go 桌面程序仅提供：

- 开启海外访问；
- 关闭海外访问；
- 当前状态和可理解的故障原因；
- 复制脱敏诊断信息。

界面不暴露协议、端口、密钥、节点选择和任意配置入口，也不直接持有管理员权限。

### 3.2 Windows 后台服务

安装包安装一个以 `LocalSystem` 运行的 Go Windows 服务。服务负责：

- 校验、启动和停止固定版本的 sing-box；
- 生成受控配置并创建/移除 TUN；
- 应用路由、DNS、QUIC 阻断和防泄漏策略；
- 进行节点及端到端健康检查；
- 发生崩溃、重启或失败时恢复网络；
- 通过受限本地 IPC 接受开启、关闭、状态和诊断指令；
- 后续读取交互式 AD 账号并申请授权。

安装需要一次管理员授权，日常开启和关闭不再弹出管理员提示。普通用户不得通过 IPC 注入任意 sing-box 配置或命令行参数。

### 3.3 VM 服务端

`172.20.9.15` 上以 Windows 服务方式运行 sing-box：

- 对员工网段提供 Shadowsocks 2022 入站；
- PoC 使用一份可统一吊销的固定测试凭据；
- 唯一互联网出站为 `127.0.0.1:8080` HTTP CONNECT；
- 不允许在上游失效时改走系统默认路由；
- sing-box 端口仅允许指定员工网段访问；
- TCP 8080 仅允许本机访问；
- SSH、RDP 和管理接口不向普通员工开放。

PIN 仍由授权管理员在电信客户端中输入。本系统不读取、保存、代填或分发 PIN。

## 4. 流量、路由与 DNS

### 4.1 路由边界

开启客户端后：

- 企业网段直连，首个已知网段为 `172.20.8.0/22`；
- AD、企业 DNS、EC 和其他内部业务网段均直连；
- 节点地址 `172.20.9.15` 强制由物理网卡直连，避免代理环路；
- 其他互联网 TCP 流量进入 TUN，经 sing-box 发送到 VM；
- UDP 443/QUIC 被阻断，使浏览器回退到 HTTPS/TCP；
- PoC 不承诺其他普通 UDP 应用可用，后续按业务明确放行或代理。

正式配置不得只依赖 RFC1918 范围判断内网；应由管理员提供完整企业网段、域名和企业 DNS 清单，并在签名策略中下发。

### 4.2 DNS

客户端接管公网域名解析，防止解析绕过、污染或错误分流。企业内部域名由 AD DNS 解析，相关 DNS 地址和内部域名后缀保持直连。关闭或卸载客户端时必须恢复原有 DNS 配置。

### 4.3 失败关闭

以下情况均不得让受代理的互联网流量回退到用户或 VM 的普通出口：

- 电信客户端退出；
- PIN 会话失效；
- `127.0.0.1:8080` 不可用；
- VM sing-box 停止；
- 客户端与节点断开；
- 配置、签名或二进制校验失败。

用户主动关闭后，程序应完整移除 TUN、临时路由、DNS 和防火墙状态并恢复开启前配置。客户端崩溃或主机重启时，由后台服务执行恢复或按有效策略重连。

## 5. 安装与用户体验

IT 提供一个签名安装包，例如 `OverseasAccessSetup.exe`。安装程序自动安装后台服务、固定版本 sing-box、TUN 驱动、快捷方式和必要防火墙规则，并写入企业策略。用户无需另行安装内核或导入配置。

日常流程：

1. 用户打开客户端并点击“开启海外访问”；
2. 后台检查企业网络、节点和运营商出口；
3. 检查通过后建立 TUN，界面显示“已连接”；
4. 用户直接使用浏览器、Git 等应用；
5. 点击“关闭”后恢复原网络。

主要状态为 `未连接`、`正在连接`、`已连接` 和 `连接失败`。错误提示至少区分：不在公司网络、无法连接服务器、运营商线路未登录或失效、本机配置失败、客户端/配置失效，以及后续的账号未授权。

PoC 不默认随 Windows 登录自动连接，由用户主动开启。以后可作为管理员策略增加自动连接。

## 6. 授权、安全与审计

### 6.1 PoC 凭据

PoC 的固定测试凭据必须随机生成，使用 Windows DPAPI 保护，并存放在仅后台服务可访问的位置。普通用户不能读取或导出明文；测试结束后可由服务端统一吊销。它不是正式上线的身份方案。

### 6.2 正式 AD 授权

正式客户端读取当前交互式账号（如 `DOMAIN\\员工号`），向 HTTPS 授权服务提交账号、设备标识、客户端版本、随机数、时间戳及设备侧证明。授权服务至少校验：

- 用户是否属于海外访问授权组；
- AD 账号是否有效；
- 当前设备是否符合企业要求；
- EC 中设备与员工关系是否匹配；
- 使用时间和策略是否允许；
- 哪些出口节点端到端健康。

AD 证明“当前是谁”，EC 关联用于证明“设备是否属于该员工”，两者不互相替代。授权成功后仅返回短期凭据、节点列表和签名策略，客户端可静默续期。调岗、离职、移出授权组或吊销后，权限立即或在短期凭据到期时失效。

### 6.3 本地与服务端安全

- UI 与高权限服务之间只开放固定 IPC 操作；
- 策略和节点配置必须验证服务端签名；
- sing-box 可执行文件固定版本并校验 SHA-256；
- 凭据、PIN、令牌和完整 URL 不写入日志；
- 卸载必须停止服务并清理网络状态；
- 8080 仅本机可达，代理端口仅授权网段可达；
- sing-box 不提供面向员工的管理接口。

### 6.4 审计

记录授权、续期、吊销、连接/断开时间、出口节点、成功/失败类型、客户端与策略版本，以及必要的聚合流量指标。默认不记录页面内容、URL 路径、账号密码等业务内容。是否记录域名应由公司合规政策单独决定。

## 7. 多节点演进

后续每台 VM 均运行独立的电信客户端、PIN 会话和 sing-box。普通四层负载均衡器无法证明电信出口真正可用，因此采用客户端选节点：

1. 每个节点检查 sing-box、8080、PIN 会话和经电信代理访问测试站点的结果；
2. 授权服务只下发端到端健康节点；
3. 客户端优先选择健康且低延迟的节点；
4. 同等条件下按用户稳定散列，减少集中；
5. 当前节点失败时切换到其他健康节点；
6. 所有节点失效时失败关闭。

首期只有 `vm101 / 172.20.9.15`，但客户端内部通过“节点提供器”获得节点。PoC 使用本地固定节点提供器，正式版替换为 HTTPS 授权服务，而不重写代理生命周期。

## 8. PoC 部署顺序

1. 在 VM 上部署并固定 sing-box 版本和哈希；
2. 配置 Shadowsocks 2022 入站及唯一 HTTP CONNECT 上游；
3. 配置 8080、本地管理端口和员工网段防火墙边界；
4. 用标准 sing-box Windows 客户端验证服务端协议链路；
5. 开发 Go Windows 服务和最小一键 UI；
6. 构建签名安装包；
7. 在一台物理 Windows 测试机完成故障及防泄漏验收；
8. 稳定后再增加 AD 授权、多节点和多人并发。

先用标准客户端验证，是为了将服务端链路故障与自研客户端故障分离。

## 9. 验收标准

### 9.1 功能与恢复

- VM 电信客户端已登录时，物理机可通过 VM 访问 Google 测试站点；
- 物理机不安装电信客户端、不输入 PIN、不手动设置浏览器代理；
- 浏览器、Git 和基础 HTTPS 请求可用；
- 企业内网、AD、企业 DNS 和 EC 保持可用；
- 主动关闭、异常退出、系统重启和卸载后无 TUN、路由、DNS、防火墙或服务残留；
- UDP 443 被阻断后，Chrome 和 Edge 正常回退到 HTTPS/TCP；
- 连续开启和关闭 20 次无网络残留。

### 9.2 防泄漏与安全

- 电信客户端退出、PIN 失效、8080 不可用或 VM sing-box 停止时，海外访问失败且不回退普通出口；
- 员工设备不能直接访问 VM 的 8080；
- 未授权网段不能连接 sing-box 入站；
- 服务端代理流量只能到达 `127.0.0.1:8080` 上游；
- 替换内核或破坏签名配置后，后台服务拒绝启动；
- 普通用户不能读取测试凭据；
- 日志不包含代理密钥、PIN、短期令牌或敏感访问内容。

### 9.3 PoC 成功条件

- 至少连续运行一个完整工作日；
- 一台物理 Windows 测试机的一键开启和关闭稳定；
- 电信链路断开和恢复能被正确感知；
- 未发现普通出口回退；
- 常用获准站点的成功率和体验满足实际办公要求。

30 人并发、AD 自动授权和生产级多节点不作为首次链路 PoC 的前置条件。

## 10. 明确不在首期范围内

- macOS 和 Linux 客户端；
- 自动读取 AD 账号并签发正式短期凭据；
- 自动多节点调度和生产负载均衡；
- 所有 UDP 协议的透明代理；
- 读取或自动填写电信 PIN；
- 绕过运营商或政府白名单；
- 替换、删除或迁移现有 WireGuard/WinNAT PoC。
