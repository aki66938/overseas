# 线路探测：Windows 通道验收（手动选择执行）

当前提交仅通过本地 TLS、注入传输与假时钟测试；**没有在真实 Windows TUN 通道执行或声称通过验证**。发布前在已批准的试点机执行以下验收，不要在普通开发机主动连接生产通道。

## 指标与协议

测量固定五个站点的 HTTPS 首响应耗时（DNS、TCP、TLS、响应头），不是带宽。HEAD 不携带 Cookie、凭据或正文，不跟随重定向；405 时可限长 GET，读取上限 1024 字节。每次独立连接，禁用环境 HTTP(S) 代理，保留标准 TLS 证书验证。2xx–4xx 表示探测可达，403/429 不表示账号或 AI 功能可用；5xx、超时和 TLS 失败均不成功。原始 HTTP 状态码保留。

连接成功立即一轮，此后每 30 秒一轮；一轮并发五目标，总预算 5 秒。手动 `probe` 与正在执行的轮次合并。超过半数目标分别连续失败三次后 quality=failed；单目标恢复成功清零，健康多数恢复正常判断。正常/较慢按成功目标的中位数划分：<1000ms 为 good，1000–5000ms 为 slow。失败只改变质量，不改变路由或连接状态。

版本 1 请求为一行 JSON：`{"version":1,"id":"route-check-1","action":"probe"}`，只能发送到本机受 ACL 保护的 `\\.\pipe\RegenBioOverseasAccess`。建议调用方上下文至少 10 秒；网络预算是 5 秒，服务端另留最多 5 秒 IPC 响应时间。响应包含 `probe_generation` 和最多五条 `probe_results`；`status` 同样携带当前代次最新结果。断开返回 `probe_unavailable`，不产生流量；重连后旧结果不作为新连接结果返回。旧 Walk JSON 协议不变。

## 试点证据

1. 在授权的 Windows 试点机上使用本次构建，记录构建 SHA、Windows 版本、连接代次、UTC 时间和 TUN 接口索引。通过现有客户端连接，不用探测脚本改路由。
2. 先在连接前读取 status/probe：应无探测流量，probe 返回 unavailable。记录物理接口和 TUN 接口的现有路由、DNS 与核心远端地址。不要保存凭据或报文正文。
3. 开始经批准的短时 Wireshark/ETW 网络捕获，同时观察 TUN 与物理接口，以及核心进程与服务进程 PID。连接后发送固定 `probe` 请求，并记录相同代次的 API 时间、目标 ID、HTTP 状态和耗时。
4. 对五个目标分别关联 DNS 结果与目的 IP：服务发起的目标 TCP/443 应由 TUN 接收；物理接口上应只见核心到既定网关/远端的封装连接，不应见服务对目标公网 IP 的直接 TCP/443。应同时检查 IPv4、IPv6。仅有 HTTP 成功、路由表、公网出口 IP 或截图不足以证明进程实际经过通道。
5. 正常连接下等待超过 30 秒确认下一轮。手动重复请求期间确认最多同一轮五个 HEAD（405 的限长 GET 除外），不存在每个请求启动一轮的重叠流量。成功结果不能证明所有海外网站可用。
6. 在一轮进行中通过现有客户端断开，确认请求被取消、后续周期不再发起探测，原有网络正常恢复。重连时记录新代次，确认 API 不返回旧代次结果。
7. 在隔离测试环境模拟目标不可达，核对三轮多数失败后 quality=failed，连接仍保持、路由没有被探测器删除；恢复后成功清零。不要通过修改生产防火墙制造故障。
